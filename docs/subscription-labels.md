# 订阅标签

订阅标签把一组可用套餐保存为可复用的节点访问规则。一个标签可绑定多个套餐，多个节点可选择同一个标签。

## 使用方式

1. 进入“订阅管理 → 订阅标签”，新建如“高付费用户”的标签。
2. 选择可使用这些节点的套餐，例如“高级月付”和“高级年付”。隐藏的老套餐同样可选。
3. 在节点编辑中选择该订阅标签并保存。已有多个节点可在节点列表勾选后，通过“批量修改 → 修改订阅标签”统一绑定。
4. 以后只需修改标签中的套餐名单，所有引用节点会使用最新名单，节点端用户列表也会通过 `node_sync` 队列刷新。

标签按用户当前 `plan_id` 判断，不按历史付款总额或价格自动分级。只给高付费用户使用的节点，应绑定仅含对应高级套餐的标签。标签独立于节点已有的展示标签 `tags`。

## 自动节点名称

订阅和 App 配置会自动按“当前倍率x (订阅标签名) 原始节点名称”生成名称。例如节点原名为 `台湾mhy 京粤闽苏专线`、倍率为 `4`、选择标签“高级”，下发名称为：

```text
4x (高级) 台湾mhy 京粤闽苏专线
```

直接复用标签名称，无需给节点逐个手填备注。动态倍率使用当前生效值，标签改名后下次更新订阅跟随新名称；清除标签则只保留倍率和原节点名称。后台存储的原始节点名称保持不变。已有相同标签备注（含全角括号）会去重；已手写倍率沿用现有兼容行为，不重复叠加。协议前缀仍由现有开关控制，并保持节点与分组引用一致。

## 权限与兼容

- 选择订阅标签后，标签的套餐名单优先于原节点的手动套餐白名单；现有权限组、用户有效期、流量与封禁检查继续生效。用户需要同时匹配节点权限组和标签内套餐。
- 未选择标签的节点继续执行原来的手动套餐规则；原限制关闭时沿用权限组。升级不会自动改写已有节点。
- 清除订阅标签会恢复节点原先的手动套餐规则。旧字段保留，批量清除标签同样恢复每个节点各自的旧规则，应在操作前核对原配置。
- 节点保存接口省略 `subscription_label_id` 时保留原绑定，显式 `null` 才清除。复制节点保留标签引用。
- 标签修改套餐名单会在事务提交后派发一次 `SubscriptionLabelSyncJob`，刷新当前绑定的在线节点；离线节点下次拉取时读取最新规则。套餐升降级沿用现有增量添加/移除用户链路。
- 使用中的标签禁止删除，数据库外键也会阻止删除。标签失效或名单为空时保持无人可用，不自动回退到开放规则。
- 删除套餐或把用户迁移到其他套餐不会自动把替代套餐加入标签。需要在标签页面显式调整名单。

规则覆盖客户端订阅、用户节点列表和节点用户鉴权。协议兼容与订阅参数策略继续在此基础上筛选；例如 Snell 是否通过 URL 开启，与节点能否被该套餐用户访问是两项独立条件。

实际鉴权应配置在独立入站/端口对应的节点；共用同一入站和用户凭据的多个展示入口沿用原有鉴权边界。已建立连接的处理继续遵循节点内核行为。

## 数据与接口

新增表 `v2_subscription_labels` 保存 `name` 与 `plan_ids`；节点新增可空外键 `v2_server.subscription_label_id`。标签名唯一，套餐列表至少包含一个存在的套餐。

管理员前缀下的接口：

```text
GET  subscription-label/fetch
POST subscription-label/save  {id?, name, plan_ids}
POST subscription-label/drop  {id}
```

标签列表含 `servers_count`。节点单次及批量保存均接受 `subscription_label_id`。

## 发布

先备份数据库，再执行本次增量迁移，并发布配套后端与管理端构建：

```sh
php artisan migrate --path=database/migrations/2026_10_15_000002_create_subscription_labels.php --force
```

按现有方式重载长驻 PHP、队列和 WebSocket 进程，确认 Horizon 消费 `node_sync`。迁移须先于依赖新字段的后端生效。本功能不要求修改 Micah 用户主题或 mi-node 通信协议。

回滚先恢复兼容代码，再回滚本迁移；回滚移除订阅标签及节点引用，原手动套餐白名单保留。回滚标签前应核对原规则，避免因恢复旧规则而扩大节点访问范围。

本地验证使用隔离 SQLite、内存缓存及模拟消息/队列；浏览器使用隔离构建与模拟管理员接口。生产迁移、MySQL 并发与真实节点连接需随发布验收。
