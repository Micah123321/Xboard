# 取消订单后的迟到支付回调

## 行为

之前普通支付回调只处理待支付订单：已取消订单直接返回成功但不入账、不触发套餐开通；BEpusdt 则返回处理失败。现在已经取消的原订单，在真实成功回调满足以下条件后恢复处理：

- 回调通过所选支付插件验签，且通知路由对应的支付配置与订单的 payment_id、支付方式一致。
- 回调 trade_no 与原订单号完全相同，网关流水号非空。相同套餐或相同价格的其他订单不会被替代或关联支付。
- 原法币报价精确到分后等于 total_amount + handling_amount（含手续费）。不以到账币数量代替法币金额，也不以本地订单金额反填回调证明。

通过后原订单从已取消变为开通中，完成既有套餐开通流程后变为已完成，记录支付时间、网关流水和支付快照。原报价保持不变；按当前用户套餐状态重判新购、续费或升级，避免旧升级单在用户已经买到同一套餐后截断现有有效期。重置流量包仍校验当前套餐是否与订单一致。

## 余额和幂等

取消和支付均先锁定用户再锁定订单，并在锁内重新读取状态。取消只对待支付订单生效，重复取消只退一次 balance_amount；旧取消请求在订单已经支付后失效。

如果订单使用了余额抵扣，取消时已退回的抵扣金额会在恢复支付时同事务重新扣回。若该余额已被使用、余额不足，订单保持已取消，回调返回失败，不产生负余额或免费权益。旧金额折抵订单还会核实被引用的历史订单仍可用，防止重复使用已折抵信用；refund_amount 仍仅在成功开通时入账一次。

支付确认、余额扣回、套餐开通及流量变更处于同一事务，开通或保存失败会整体回滚，后续正确回调可重试。完成订单的重复回调不会再次扣余额、增加套餐时长或发放流量。订单成功与支付成功钩子在最外层事务提交后触发，回滚则丢弃。提交后的插件钩子异常会记录错误，不改变已落库的成功状态，也不会阻断后续支付成功事件；钩子自身的失败副作用需根据错误日志单独补偿。旧金额折抵来源在所有订单的统一开通入口校验并锁定，避免恢复的取消单与另一待支付单重复使用同一来源。

## 支付通道

- TokenPay：验签成功状态为 1，使用 ActualAmount（原法币金额），不使用 PayAmount 等未确证别名。
- BEpusdt：使用既有的 expected_amount（整数分）及原 amount，保留币种、支付配置和手续费的锁内校验；等待、超时通知不认定支付。
- EPay：成功状态为 TRADE_SUCCESS，透传验签覆盖的 money 原报价。
- AlipayF2f：沿用既有签名和 TRADE_SUCCESS 检查，透传 total_amount 原报价。
- 其他旧插件：待支付订单沿用现有流程；缺少可靠原金额的已取消订单保持取消，需插件提供可信金额契约后再启用恢复。

无新增数据库迁移，不涉及用户前端或 mi-node 修改，不会扫描历史取消订单自动补单；由网关后续正确回调触发。
