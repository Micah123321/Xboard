# 节点多入口与 TCP 故障转移

在节点编辑的地址、连接端口下方开启“随机入口”，添加额外的地址与连接端口。原“节点地址 + 连接端口”作为主入口，和最多 20 个额外入口共同参与选择。域名、IPv4、IPv6 均可使用；每组端口须为 1–65535 的单个整数，重复组合会在保存时提示。

每次生成订阅时，为每个节点等概率随机选择一组完整入口，保持一个节点条目。连续两次订阅可以选中同一组。节点 ID、父子关系、用户认证、倍率、服务端监听端口及协议配置保持原有含义。所有入口应转发到同一节点服务；本功能只改变客户端连接地址和连接端口。

关闭“随机入口”后，额外入口配置保留，只下发主入口。未配置多入口的旧节点继续支持现有动态端口范围；启用随机入口时，主连接端口也须为单个整数。

## TCP 检测

沿用现有仅对子节点开放的“TCP 端口检测”。开启检测并开启随机入口后，Shadowsocks 节点对每组入口执行真实加密代理请求：面板通过入口连接到节点，再经节点访问 HTTPS 检测地址，只有证书验证成功并收到 HTTP 204 才视为可用。转发账户额度耗尽但仍接受 TCP 连接的入口，不再仅凭端口连通加入候选。其他协议继续检测 TCP 连接。订阅只从最近检测可用的入口中选择。关闭随机入口时，保留旧节点按服务端口检测的行为。

- 一个入口故障，下一轮检测后跳过该入口；其他可用入口继续下发。
- 全部入口故障时，停止下发该节点；开启“自动上线”时同步隐藏。
- 入口恢复后，后续检测重新将其加入候选；开启“自动上线”时恢复显示。
- 未检测、配置变更后尚未完成检测、健康缓存过期时，暂不下发该入口池。
- 关闭 TCP 检测时，从全部配置入口随机选择。

调度命令为 `php artisan sync:server-tcp-checks`，现有 Laravel Scheduler 每分钟执行一次。健康缓存有效期为 180 秒，包含节点配置指纹，避免复用旧地址的检测结果。Shadowsocks 还绑定协议、父节点协议和探测配置，并隔离旧 TCP 健康缓存。多个节点分批并发探测，每批 8 个节点；普通 TCP 等待 2 秒，Shadowsocks 每入口默认最多等待 5 秒，每个入口池最多并发 8 个请求，各节点工具并发启动。

保存开启检测的子节点时会立即执行一次检测，后续由调度器更新。Shadowsocks 多入口验证实际 TCP 代理数据往返，不单独验证 UDP；其他协议的 TCP 检测仍不代表实际转发可用。探测失败说明该入口当前无法完成代理请求，不能单凭结果区分额度耗尽、线路故障或目标站故障。客户端需重新获取订阅才会收到新入口，现有连接不会因此自动迁移。

## Shadowsocks 探测工具

配套工具位于 mi-node 项目的 `cmd/mi-entry-probe`。它是安装在**面板和 Scheduler 容器/主机**上的独立命令，不需要更新运行中的 mi-node 服务或用户前端。支持普通 TCP Shadowsocks 和库支持的 AEAD / SS2022 加密方法；SIP003 插件不在本次支持范围，配置插件时不会降级为仅 TCP 可用。

在 mi-node 仓库使用 Go 1.26 或兼容工具链编译，选择与面板环境一致的平台：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o mi-entry-probe ./cmd/mi-entry-probe
```

项目的生产与本地 Dockerfile 已自动构建并安装 `/www/bin/mi-entry-probe`，配套 mi-node 源码固定为 `9f5d4b66cf58463d36a49e4da9fe21c0ee030de8`，会随四类后端容器部署；无需在每次重建后手动安装。非 Docker 部署需将工具安装到面板项目的 `bin/mi-entry-probe` 并赋予 Scheduler/PHP 进程执行权限，或通过环境变量指定绝对路径。若采用独立 Scheduler 容器，必须同时挂载工具。发布 PHP 代码前先准备工具，再加载配置、重启长驻进程并执行一次检测。仅更新 PHP 而遗漏工具时，此类入口池会被排除，日志记录固定错误类别。

可选配置：

```dotenv
SERVER_ENTRY_PROBE_BINARY=/www/bin/mi-entry-probe
SERVER_ENTRY_PROBE_URL=https://www.gstatic.com/generate_204
SERVER_ENTRY_PROBE_TIMEOUT=5
# 可选：指定父节点允许访问的有效专用探测用户 ID
SERVER_ENTRY_PROBE_USER_ID=0
```

检测地址必须为 HTTPS、证书有效且返回 HTTP 204，无重定向；可以替换为自建检测地址。工具不会使用环境 HTTP 代理，也不会绕过证书验证。目标地址不可达可能使全部入口暂时下架，需选择节点出口可稳定访问的地址。

认证复用实际父节点下发的有效用户列表，优先选择无设备数限制的账户，也可指定专用账户。要求账户未封禁、未过期、有剩余用户流量且符合父节点权限组/套餐限制；没有有效账户时不下发入口池，并在日志提示配置父节点有效探测账户。若父节点仅下发独立子节点身份、没有基础用户，本次检测需先配置一个有效的父节点专用账户；不借用隐藏后会被撤销的子节点身份，以保证故障后能够自动恢复。父子节点加密方式必须一致且均未启用插件，否则不将该入口池视为可用。SS2022 密码沿用父节点服务密钥派生规则。即使子节点已被自动隐藏，仍可使用父节点身份检测恢复，避免隐藏后无法重新上线。探测会消耗少量真实转发流量并按现有规则计入所选账户，建议配置专用账户。

凭据仅通过子进程 stdin 传递，不进入命令行、临时文件或日志。工具缺失、超时、退出失败、响应条目错配或没有有效账户时均不会回退到仅 TCP 判断；旧的健康结果也不会继续沿用。

## 上线

发布前核实所有启用 SS 多入口节点均有兼容的父节点和可用基础身份；同时估算按 8 个节点分批的全轮探测时间，连同调度间隔必须小于 180 秒健康缓存期限。大量入口或较大超时时间可能超过该容量，须先调整刷新机制。当前生产预检为 3 个检查子节点、2 个 SS 入口池，网络截止时间上界约 10 秒，加调度余量约 70 秒。

已启用多入口的系统应用本次修复不需要新增迁移，需先安装探测工具，再发布 PHP 和管理端资源、重启相关长驻进程并执行 `php artisan sync:server-tcp-checks`。客户端随后更新订阅。

首次部署多入口功能时，还需执行已有数据库迁移及管理端构建：

```sh
php artisan migrate --force
cd admin-frontend
npm run build
```

新增迁移：`2026_10_18_000002_add_server_entry_points.php`，为 `v2_server` 添加 `entry_points_enabled` 和 `entry_points`。默认关闭，不更改已有节点的入口选择。

节点监听和流量上报协议不变；无需更新用户前端或运行中的 mi-node。Shadowsocks 真实链路检测需先在面板及调度环境安装上文的独立探测工具，本次修复没有新增数据库迁移。
