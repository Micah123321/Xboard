# 子节点单独倍率

已有子节点可以开启 `child_rate_enabled`，继续共用父节点的监听端口。面板为该子节点生成独立订阅凭据，mi-node 保留独立认证身份上报流量，面板再按子节点的基础倍率或动态倍率结算。流量扣量累加到同一个真实账户；同一父节点监听内，各订阅身份共享该账户的限速和设备数。

以父节点 461 和子节点 484 为例：父节点倍率保持 4，编辑现有子节点 484，开启“子节点单独倍率”并把倍率设为 3。直接身份的 100 字节按 400 字节扣量；子节点新订阅身份的 100 字节按 300 字节扣量。无需新建节点、端口或监听进程。其他未开启的子节点保持原计费方式。

## 更新与启用

1. 更新面板代码并运行 `php artisan migrate`，再按现有发布方式更新管理前端和重启队列工作进程。迁移默认关闭全部现有节点的开关。
2. 更新承载父节点的 **64 位 mi-node** 并重启该服务，等待它完成一次用户或配置同步。新版通过 `X-Mi-Node-Child-Rate: 1` 声明能力；面板在能力未确认时阻止开启。先更新面板，再更新节点。
3. 编辑已有子节点，在“父节点”下方开启“子节点单独倍率”，设置原有倍率字段并保存。父子节点需要相同协议；Hysteria 版本及 Shadowsocks 加密方式也需要一致。Snell 不适用。
4. 用户刷新订阅并重新连接。新订阅密码与原密码不同；旧订阅身份仍按父节点倍率结算。关闭开关后，也应刷新订阅恢复原身份。

此实现按**订阅认证身份**分账，共用入口本身没有核实流量经过哪条物理中转线路。持有低倍率凭据的人仍可尝试把它用于其他可达路径；线路来源绑定不属于当前实现。

## 账务与维护

父节点普通流量和各独立子身份在同一事务内结算；根账本校验完整报告，子账本使用派生报告编号，重复报告不重复扣量。访问明细按同一映射落到真实用户和对应节点。倍率在面板接收报告时确定，队列重试保持该快照。

禁用、变更权限或移动子节点时会重新同步父节点用户列表；历史身份映射保留供旧连接尾流与持久报告重试使用。修改协议后仍可按历史身份处理尾流。启用单独倍率的子节点不会在机器自动发现中启动第二个监听。

删除计费节点或回滚数据库前，应先停止新增连接并处理完待上报与待结算数据。不要提前删除身份表或 mi-node 的报告持久文件；已删除节点的报告按现有账务约束报错并等待处理。单独关闭开关不会删除身份映射。

## 已验证范围

包含开关默认值及保存、旧节点能力限制、父子协议/层级约束、权限组与套餐隔离、身份稳定性、共用真实账户限制、订阅凭据一致性、混合流量扣量、重试去重、冲突检查、整批回滚、停用后改协议尾流，以及访问明细与账单两种到达顺序的对账测试。HTTP 集成使用隔离 SQLite 数据库；Redis 通知使用测试替身。

Go 已通过相关包回归，并在真实 Hysteria2/QUIC 入站上验证三个身份共用同一个 UDP 端口完成 TCP echo：流量和访问明细保留各自认证 ID，在线状态只记录一个真实账户。真实连接测试同时发现并修正了把监听地址记作访问目标的问题；路由改写与 fake-IP 原始目标也有回归覆盖。

管理前端已通过类型检查、28 项交互与相关回归测试和独立目录构建；未对已部署管理界面进行浏览器实测。PHP 按测试类隔离运行的 205 项相关测试全部通过。变更尚未执行线上迁移或部署。
