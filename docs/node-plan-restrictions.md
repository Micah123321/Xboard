# 节点套餐限制

在管理员的节点编辑弹窗开启“启用套餐限制”，多选允许使用的套餐后保存。同一节点可选择多个套餐；一个套餐也可用于多个节点。隐藏的老套餐仍可选择。

## 访问规则

用户须满足现有有效期、流量和封禁规则，并同时命中节点权限组与套餐白名单。未开启套餐限制的节点继续仅按现有权限组分配。白名单依据用户当前 `plan_id`，与套餐价格、历史付款和是否上架无关。

- `plan_restriction_enabled`：是否启用，数据库默认 `false`。
- `allowed_plan_ids`：允许使用的套餐 ID 数组。开启时至少选一个存在的套餐。
- 关闭限制保留已有套餐选择；启用状态下名单为空时无人可用。
- 删除套餐不会自动把替代套餐加入白名单；管理员可移除“已删除”的选中项并重新选择。
- 用户前端节点列表、客户端订阅、节点 REST 拉取及 WebSocket 全量/增量同步均执行套餐限制。
- 用户同权限组内切换套餐也会重新授予或撤销节点资格；节点白名单修改触发全量同步。
- 套餐强制同步和删除套餐时的用户批量迁移通过 `node_sync` 队列刷新受影响权限组，任务在数据库事务提交后执行。

## 上线步骤

先在目标环境按现有运维方式备份数据库，再执行本次增量迁移，之后启用对应后端与管理端构建：

```sh
php artisan migrate --path=database/migrations/2026_10_15_000001_add_plan_restrictions_to_v2_server_table.php --force
```

管理端在 `admin-frontend` 目录运行 `npm run build`，默认输出到 `public/assets/admin`；也可通过现有 `ADMIN_BUILD_OUT_DIR` 指定输出目录并随前端镜像部署。按部署方式重载长驻 PHP、队列和 WebSocket 进程，确认 Horizon 正在消费 `node_sync`。本次无需修改 Micah 用户主题或 mi-node 通信协议。

迁移支持回滚；回滚应先恢复兼容的后端和管理端版本。取消某个节点的限制可直接关闭开关，无需回滚数据库。

## 鉴权边界

限制应配置在实际执行用户鉴权的节点。多个域名或中转入口若共用同一个入站与凭据，只在展示节点上设置不同白名单不足以隔离实际连接；分别控制线路应使用独立入站/端口。用户凭据从节点移除后的已有连接处理沿用节点内核行为，本功能不额外强制断开所有已建立连接。

## 本地验证

后端专项测试使用隔离 SQLite，覆盖权限组与多套餐交集、空白名单、有效期/流量/封禁、套餐升降级、白名单变更、旧客户端保留字段、套餐删除迁移和强制同步；接口测试覆盖真实订阅内容及节点列表 ETag。管理端脚本验证字段映射与节点兼容行为，浏览器脚本位于 `output/node-plan-restriction-verify.cjs`，使用模拟接口验收交互，未连接生产节点。
