# mi-node 后台更新与首次接入

后台、管理端和节点执行器已发布。节点自动发现沿用已有面板绑定；显示版本信息不要求登记票据。远程托管升级仍需单独启用。

## 更新对象

面板的一个逻辑节点不等于一份可执行程序。同一 mi-node 安装可以同时运行多个节点、绑定多个面板；更新二进制会重启该安装下的全部绑定。因此后台按安装实例选择更新对象，一份安装只登记到一个更新管理面板。其他绑定的面板继续管理业务。

自动更新默认关闭。后台先登记固定版本、对应 Linux 架构的 mi-node 和 xbctl 制品、文件大小与可信构建生成的 SHA256，然后为指定安装选择目标版本。启用全局与安装策略后，创建限制并发的批次。建议先选一个实例验收，再扩大批次；失败暂停后先检查原因。

## 升级后自动显示

在节点执行 `sudo xbctl upgrade --version dev`。新版启动后自动使用已有 HTTP 或 HTTPS 面板绑定上报安装标识、mi-node 版本和架构；后台“节点更新”的默认页会在“自动发现的节点”中显示。无需填写实例 ID、下载票据或更换原面板地址。安装标识持久保存在节点本地，同一安装下的节点共享标识；后台各行按经过认证的逻辑节点 ID 区分。

只有包含自动发现功能的新版会发送这些信息。旧版已正常运行的节点无需停用，升级后开始上报即可出现。发现上报失败不影响流量计费和业务启动。

## 启用远程托管升级

自动发现只展示版本，不开启二进制替换权限。需要后台下发远程升级时，再用后台生成的限时登记票据登记安装。票据和安装凭据使用本地受限文件保存，不放进 URL、日志或 shell 命令参数。

自动更新由独立 systemd timer/oneshot 服务执行，以便主 mi-node 服务重启失败后仍能完成回滚。普通 `xbctl upgrade` 手工入口保留，并与自动更新共用锁；配置、证书、流量待报文件均保留。

后台登记弹窗下载 JSON 前，填写 `xbctl list` 展示的本机绑定实例 ID。下载文件含 `instance_id`，更新器仅用它读取已有认证配置；服务端权限仍来自管理员票据的 scope。将票据放到节点后设置 0600 权限，再运行：

```sh
xbctl update-agent install --authority-panel-url https://PANEL_HOST --enrollment-file /root/mi-node-enrollment.json
xbctl update-agent status
```

安装会启用独立的 `mi-node-update.timer`，但全局和安装策略仍默认关闭。`xbctl update-agent disable` 检查在途事务后停用 timer；不要直接清除事务或待报记录。

原手动入口 `xbctl upgrade --version VERSION` 与 `bash install.sh upgrade` 共用安装锁。未登记安装若手动升级中断，可用 `xbctl upgrade --recover` 检查并恢复手工事务；自动事务仍由更新器恢复。旧手工发行缺少发布者 SHA 时保留兼容检查，本地恢复哈希不等于可信发布校验。脚本升级依赖 `flock`、`realpath`、`sha256sum`、`jq`、`sync`。

首版自动更新适用于 Linux amd64/arm64 的 systemd 宿主安装。Docker 节点通过镜像部署更新，OpenRC 保留手工升级；后台显示实际能力。

## 故障处理

- 校验失败发生在替换前，旧版本继续运行。版本明确固定，不使用浮动 latest 自动追更。
- 升级后需要进程与业务初始化健康检查，单凭 systemctl restart 成功不会标记升级成功。
- 替换、重启或健康检查失败时还原双二进制并验证旧版本；回滚失败保留现场。
- 面板暂时离线时，本机已开始的替换事务继续验证或回滚，恢复网络后补报。
- 租约失联标记 uncertain 并暂停批次，仍占并发名额；不会因超时而把同一安装发给另一个执行器。管理员先核实该安装的执行器与本地事务状态，再在后台处理失联任务。
- 取消批次停止尚未进入安装的任务；已开始的事务继续完成或回滚，避免停在两文件版本混合状态。

## 面板容器发布

面板/队列/调度/WebSocket 共用后端镜像，新增功能及数据库迁移须发布到同一镜像版本。先备份数据库和原镜像引用，执行新增迁移后再重建全部相关进程。独立管理端也需更新镜像。新表和默认关闭策略不会要求已有节点立即升级。

生产 Compose 模板位于 `deploy/xboard-server/compose.production.yaml`。用户端端口变量为 USER_PORT，管理端为 ADMIN_PORT，代理后端默认 http://web:7001。执行时沿用既有 Compose 项目名与数据目录，避免意外创建空 Redis 卷。

流量修复迁移和节点本地待报批次要求详见 `docs/traffic-accounting-upgrade.zh-CN.md`。本说明不表示已连接生产服务器、发布镜像或执行节点更新。

## 本地验收结果

后端联合回归 47 项、295 个断言通过；管理页面 7 项逻辑测试、两前端类型检查与构建通过。Edge 隔离模拟接口检查了实际渲染、四个页签和设置提交幂等键。节点 11 个相关包通过，Linux WSL 实跑文件锁、ACK 恢复与手动脚本回滚测试；Linux amd64/arm64 的完整功能节点及 xbctl 编译通过。

`mi-node/output/update-build` 的二进制为 dev 验证产物，不是后台自动更新发行：正式发布需选定不可变语义版本，使用版本 ldflags 重新构建并登记对应大小/SHA256。真实 systemd 整机更新、生产数据库并发和线上回滚仍需从单个实例灰度验收。
