# mi-node 自动接入与在线更新

新版 mi-node 启动后沿用已有面板绑定自动接入在线更新。面板地址、机器或节点范围、认证信息从节点本机现有配置读取；无需票据、下载接入文件、填写本机实例 ID，亦无需手动安装更新 agent。

## 日常使用

推送节点代码到 main/master/dev 后，CI 测试通过并构建 Linux amd64/arm64 的 mi-node 和 xbctl，发布独立固定版本与 node-release.json。下载 URL、SHA256 和文件大小由实际构建生成。面板每五分钟同步版本清单，也可点击‘检查新版本’立即同步。

在‘节点更新 → 节点与更新’中点击每行右侧的‘在线更新’：已自动接入的节点可直接安装最新版或打开‘自动跟随最新版’；接入尚未完成时显示等待状态，每五秒自动检查，成功后自动切换为更新操作。旧节点的能力标记与新版区分，查询网络错误不会误判为未接入。

自动接入与自动安装是独立设置。新登记默认关闭自动安装，用户可执行一次性更新；全局自动更新及安装的跟随最新版策略同时开启后，后台自动创建受并发限制的升级任务。无需手填固定版本、制品散列或批次。

## 自动接入与执行器

节点使用现有绑定认证请求 HTTPS `/api/v2/server/update/auto-enroll`。机器绑定验证有效机器 token，旧节点绑定验证现有 server_token 与准确节点范围。安装 ID 与随机 agent token 在请求前持久化，重复请求幂等；凭据只存散列，接入失败自动重试。认证失败、范围重叠或被撤销的登记不会被自动覆盖。

一份 mi-node 安装只选择一个管理面板；既有登记优先保留原 authority，其他面板继续业务。自动接入不改变已有更新策略，也不恢复本地已停用的执行器。业务发现 ID 可以复用于新自动登记，已存在的手工登记身份保留。

主进程只引导独立 systemd 服务；登记、版本检测和文件替换在 mi-node.service cgroup 外执行，主服务退出或重启不会取消独立执行器。启动接入失败不阻塞业务，面板暂时离线时独立定时任务会继续重试。

原生 Linux amd64/arm64、systemd 及固定二进制布局支持此流程。Docker 通过镜像部署，OpenRC 保留原部署升级方式。手工票据登记保留在高级设置，用于特殊登记流程，普通节点走自动接入。

## 已运行旧版本如何衔接

旧 SHA `ef587955b32257daa5f96f679ba33b2f94913e42` 的 mi-node 有业务配置同步，启动时没有自动接入更新执行器的逻辑，也没有面板下发任意安装命令的入口。仅更新面板不使旧进程执行新增逻辑。通过现有节点部署方式换成本次新版 mi-node/xbctl 后，新版启动自动完成接入，后续使用面板在线更新。

首次上线本次功能需要同步发布后端、管理前端和节点二进制；节点无需额外的接入命令、票据或绑定变更。固定发行不可变；dev 兼容下载入口跟随已经完整发布的 latest，保留历史 dev git 标签。新版 xbctl 和安装脚本的 --version dev 直接使用 latest 下载路径，旧 xbctl 的 dev 下载由 CI 同步兼容产物。

## 发布和迁移

默认版本源为 https://github.com/Micah123321/mi-node/releases/latest/download/node-release.json。`MI_NODE_RELEASE_MANIFEST_URL` 可设置自建 HTTPS 清单，`MI_NODE_RELEASE_AUTO_SYNC=false` 可关闭定时同步。首次发布前缺少清单或源临时不可用时保留已登记的版本数据。

本次自动接入新增迁移 `2026_10_12_000002_add_node_auto_enrollment_capability.php`，给发现记录增加默认 false 的 `auto_enroll_supported`。此前的 `2026_10_12_000001_add_node_update_latest_policies.php` 保留。部署后执行 `php artisan migrate --force`，重建后端、队列与调度进程，发布管理前端，沿用原 Compose 项目与数据卷。确保 schedule:work 或 cron 正常运行；`php artisan node-update:sync` 可验证清单同步。

## 自动接入失败诊断

节点已报告固定版本号但仍等待登记时，查看 mi-node-update-bootstrap.service 的状态与日志。已修复两项阻断：EnvironmentFile 的绝对路径带字面引号被 systemd 忽略；布局检查对 getty@.service 等无实例模板执行 systemctl show 导致退出。修复后跳过模板定义，继续检查实际实例与真实共享二进制，别名按规范服务 ID 比对。相关服务文件用真实 systemd-analyze verify 验证，布局遍历也在运行中的 systemd 上验证。

## 更新与恢复

一次安装会重启同一共享二进制下的全部绑定，包括其他面板绑定。任务冻结版本、URL、SHA256 和大小，新发布不会改变正在执行的目标。下载、双文件校验、备份与安装闸门完成后才替换。重启或健康检查失败会还原双二进制并验证旧版，配置、证书和流量待报文件保留。

面板暂时离线时本地已开始的事务继续验证或回滚，恢复后补报；失联任务保留容量并暂停批次，待实际核验。取消批次或关闭自动更新只阻止尚未开始安装的任务。失败或人工取消后不会不断重复尝试同一发行。
