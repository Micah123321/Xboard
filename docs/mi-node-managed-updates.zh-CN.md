# mi-node 后台更新与首次接入

后台、管理端和节点执行器已发布。节点自动发现沿用已有面板绑定；显示版本信息不要求登记票据。远程托管升级仍需单独启用。

## 更新对象

面板的一个逻辑节点不等于一份可执行程序。同一 mi-node 安装可以同时运行多个节点、绑定多个面板；更新二进制会重启该安装下的全部绑定。因此后台按安装实例选择更新对象，一份安装只登记到一个更新管理面板。其他绑定的面板继续管理业务。

代码推送到 mi-node 的 main/master/dev 分支后，CI 通过测试并构建 Linux amd64/arm64 的 mi-node 与 xbctl，自动生成独立版本和 node-release.json。下载地址、SHA256、文件大小均来自实际构建产物，无需在后台逐项填写。面板每五分钟同步清单，也可在‘节点更新’点击‘检查新版本’立即同步。

已登记的安装会显示当前版本、可用最新版和比对状态。点击‘安装最新版’创建一次性任务，与自动更新开关独立；开启全局自动更新和安装的‘跟随最新版’后，面板自动选择兼容的新版本并生成受并发限制的批次。失败或人工取消后不会持续重试同一发行，需要检查原因后手动重试。高级固定版本策略和批次预览仍可使用。

默认版本源为 https://github.com/Micah123321/mi-node/releases/latest/download/node-release.json。自建发布源可在部署配置设置 MI_NODE_RELEASE_MANIFEST_URL；MI_NODE_RELEASE_AUTO_SYNC=false 可关闭定时同步。源地址须为 HTTPS，清单须使用同一契约。首次新流程发布前，旧发行没有清单时会显示等待构建或同步失败，已登记版本与业务上报继续保留。

## 升级后自动显示

在节点执行 `sudo xbctl upgrade --version latest`。新版启动后自动使用已有 HTTP 或 HTTPS 面板绑定上报安装标识、mi-node 版本和架构；后台“节点更新”的默认页会在“自动发现的节点”中显示。无需填写实例 ID、下载票据或更换原面板地址。安装标识持久保存在节点本地，同一安装下的节点共享标识；后台各行按经过认证的逻辑节点 ID 区分。

只有包含自动发现功能的新版会发送这些信息。旧版已正常运行的节点无需停用，升级后开始上报即可出现。发现上报失败不影响流量计费和业务启动。

## 从节点列表进入在线更新

在‘节点更新 → 节点与更新 → 自动发现的节点’中，点击每一行固定在右侧的‘在线更新’按钮。窗口使用节点 ID 查询实际的有效托管登记，不要求在下方安装表中寻找，也不把业务发现 ID 当成更新 agent 的安装 ID；已撤销登记会跳过，查询会继续翻页直到找到有效登记或确认没有登记。

已有登记时，窗口展示更新执行器状态、当前版本与可用最新版，可直接安装或打开自动跟随最新版。没有登记时，窗口展示一次性接入步骤；点击‘为此节点生成接入票据’会预填节点或机器范围，本机绑定实例 ID 使用 xbctl list 的实际结果。查询失败显示可重试错误，不会当作未登记。全局自动开关不会替节点安装 update-agent。

此入口补丁仅涉及管理前端，后端沿用已部署的 installations、policy、enrollments 与 update-latest 接口，无新增迁移。重新发布管理前端后入口生效。

## 启用远程托管升级

自动发现只展示版本，不开启二进制替换权限。需要后台下发远程升级时，再用后台生成的限时登记票据登记安装。票据和安装凭据使用本地受限文件保存，不放进 URL、日志或 shell 命令参数。

自动更新由独立 systemd timer/oneshot 服务执行，以便主 mi-node 服务重启失败后仍能完成回滚。普通 `xbctl upgrade` 手工入口保留，并与自动更新共用锁；配置、证书、流量待报文件均保留。

后台登记弹窗下载 JSON 前，填写 `xbctl list` 展示的本机绑定实例 ID。下载文件含 `instance_id`，更新器仅用它读取已有认证配置；服务端权限仍来自管理员票据的 scope。将票据放到节点后设置 0600 权限，再运行：

```sh
xbctl update-agent install --authority-panel-url https://PANEL_HOST --enrollment-file /root/mi-node-enrollment.json
xbctl update-agent status
```

安装会启用独立的 `mi-node-update.timer`，但全局和安装策略仍默认关闭。`xbctl update-agent disable` 检查在途事务后停用 timer；不要直接清除事务或待报记录。

原手动入口 `xbctl upgrade --version VERSION` 与 `bash install.sh upgrade` 共用安装锁。未登记安装若手动升级中断，可用 `xbctl upgrade --recover` 检查并恢复手工事务；自动事务仍由更新器恢复。旧手工发行缺少发布者 SHA 时保留兼容检查，本地恢复哈希不等于可信发布校验。脚本升级依赖 `flock`、`realpath`、`sha256sum`、`jq`、`sync`。

首版自动更新适用于 Linux amd64/arm64 的 systemd 宿主安装。Docker 节点通过镜像部署更新，OpenRC 保留手工升级；后台显示实际能力。

## 故障处理

- 自动追更先解析最新版，再冻结任务的版本、URL、大小和 SHA256。执行时使用固定发行快照，后续发布不会改变正在安装的目标；校验失败发生在替换前，旧版本继续运行。
- 升级后需要进程与业务初始化健康检查，单凭 systemctl restart 成功不会标记升级成功。
- 替换、重启或健康检查失败时还原双二进制并验证旧版本；回滚失败保留现场。
- 面板暂时离线时，本机已开始的替换事务继续验证或回滚，恢复网络后补报。
- 租约失联标记 uncertain 并暂停批次，仍占并发名额；不会因超时而把同一安装发给另一个执行器。管理员先核实该安装的执行器与本地事务状态，再在后台处理失联任务。
- 取消批次停止尚未进入安装的任务；已开始的事务继续完成或回滚，避免停在两文件版本混合状态。

## 面板容器发布

本次新增迁移 2026_10_12_000001_add_node_update_latest_policies.php，给既有安装与批次增加 follow_latest/manual 字段，默认关闭；部署时执行 php artisan migrate --force。确保 schedule:work 或 cron 正常运行，可用 php artisan node-update:sync 检查清单同步。面板/队列/调度/WebSocket 共用后端镜像，新增功能及数据库迁移须发布到同一镜像版本。先备份数据库和原镜像引用，执行新增迁移后再重建全部相关进程。独立管理端也需更新镜像。新表和默认关闭策略不会要求已有节点立即升级。

生产 Compose 模板位于 `deploy/xboard-server/compose.production.yaml`。用户端端口变量为 USER_PORT，管理端为 ADMIN_PORT，代理后端默认 http://web:7001。执行时沿用既有 Compose 项目名与数据目录，避免意外创建空 Redis 卷。

流量修复迁移和节点本地待报批次要求详见 `docs/traffic-accounting-upgrade.zh-CN.md`。本说明不表示已连接生产服务器、发布镜像或执行节点更新。

## 本地验收结果

发现节点在线入口补丁：管理前端 19 项测试、类型检查与构建通过；浏览器使用隔离接口验证逐节点查找托管安装、弹窗直接安装和自动跟随、首次接入指南及预填票据范围。此结果不表示已更新线上管理前端或执行真实节点安装。

本轮后端更新与发现回归 30 项、253 个断言通过；管理页面 15 项逻辑测试、类型检查与生产构建通过。Edge 使用隔离接口验证实际最新版渲染、清单同步、无固定版本的自动策略保存、关闭全局自动时单次安装，以及版本源失败保留节点列表。Linux WSL 实跑 updateagent/scripts 包测试；四个 Linux amd64/arm64 的完整功能节点及 xbctl 编译通过，生成的清单通过 PHP 契约、SHA256/大小/ELF 架构校验，amd64 二进制内置版本实际运行一致。真实服务替换与回滚未执行。

新流程的本地验证产物位于 mi-node/output/auto-update-build，包含四个二进制及自动生成的清单，仅用于本地验收。正式版本由推送后的 CI 构建和发布，面板自动同步；本地修改不等于线上已部署。旧 dev/SHA 构建或尚无 update-agent 的安装，需首次执行 `xbctl upgrade --version latest`（也可指定新固定版本）并接入 agent，之后即可使用后台单次安装和自动追更。新流程不再移动旧 dev 标签，`--version dev` 会继续下载旧发行；请使用 latest 或新固定版本。真实 systemd 整机更新与线上回滚仍需从单个实例灰度验收。
