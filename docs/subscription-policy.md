# 订阅下发策略

管理入口：订阅管理 → 订阅下发策略（`#/subscriptions/distribution`）。

该页面按协议管理默认下发范围、是否允许订阅 URL 参数覆盖，以及参数名。初始配置中 Snell 默认不下发，其余协议继续默认下发。配置保存到现有 `v2_settings` 的 `subscribe_protocol_policies`，无需新增数据库迁移。

## URL 用法

以下示例使用默认参数名和默认订阅路径；TOKEN 表示原订阅令牌。站点自定义订阅路径时，在原订阅链接上追加参数即可。

```text
/s/TOKEN                         默认不含 Snell
/s/TOKEN?snell=1                 显式包含 Snell，保留其他默认协议
/s/TOKEN?snell=0                 显式排除 Snell
/s/TOKEN?snell=1&mieru=0         包含 Snell，排除 Mieru
/s/TOKEN?snell=1&types=snell      只请求 Snell
/api/v1/client/subscribe?token=TOKEN&snell=1
```

原地址已有 `?` 时用 `&` 追加参数。`types`、`filter`、`flag` 继续沿用现有作用；仅 `types=snell` 或 `types=all` 不会自动开启默认关闭的 Snell。未知协议的 `types` 不会扩大为全部协议。

参数值仅接受标量 `1` 或 `0`。未知值、数组和未携带参数都使用默认下发设置。URL 参数区分大小写。

## 页面配置

- 默认下发：未携带有效覆盖参数时是否包含该协议。
- 允许参数覆盖：开启后允许通过 `参数名=1` 或 `参数名=0` 覆盖默认值；关闭后参数被忽略，仅按默认下发。
- URL 参数名：小写英文字母开头，仅含小写字母、数字、下划线，长度 1–32 字符。各协议参数名须唯一，且避开 `token`、`flag`、`types`、`filter` 等系统保留名。
- 参数更名保存后，旧参数名不再覆盖该协议。页面会同步显示新的最短 Snell 示例及其他参数组合。

加载失败时禁止保存，保存失败保留编辑内容。刷新或离开页面时保护未保存修改。

## 访问与兼容顺序

后端先获取用户现有可用节点（权限组、套餐白名单等），再应用订阅下发策略，随后执行客户端格式和协议兼容过滤。URL 参数只筛选已有权限的节点，不授予额外节点资格，也不改变节点端的用户鉴权。

Snell 需要显式开启且客户端支持：Mihomo 内核已知版本低于 `1.19.26` 时仍被过滤，即使 URL 设置 `flag=meta` 或提供其他格式标记也会保留真实 User-Agent 中的内核检查。包装客户端版本不视作 Mihomo 内核版本；未知内核版本沿用已有兼容行为，显式开启前应确认客户端支持。Surge 继续执行现有 Snell v4 兼容规则。

策略仅影响客户端订阅导出，用户主题的节点列表与节点后端用户鉴权沿用现有行为。

Surge、Surfboard 模板的 `$subs_link` 刷新地址保留有效协议参数，以及 `flag`、`types`、`filter`；不转发无关查询内容，避免托管自动刷新丢失协议选择。

## 部署与验证

发布对应后端与管理端构建，并按现有流程重载 PHP 常驻进程。本功能没有数据库结构变更。功能生效后，原有 Snell 订阅默认隐藏 Snell，需要给原地址追加开启参数，或在页面调整默认下发。

验证包含隔离 SQLite 中的设置保存、两类真实订阅地址、管理员身份检查、套餐权限与版本过滤；管理端使用模拟 API 验证规则编辑、参数校验、保存回显、错误恢复与手机布局。未连接真实代理节点或进行生产发布。
