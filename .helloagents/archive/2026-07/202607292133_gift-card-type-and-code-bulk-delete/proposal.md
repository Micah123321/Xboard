## 1. 需求

### 背景
礼品卡模板接口已构造 `type_name`，但分页响应仍返回原始集合，导致管理端模板列表取不到该字段并显示空类型标签。兑换码管理仅支持逐条删除，无法高效清理一批未使用兑换码。

### 目标
- 所有模板列表中的类型稳定显示，即使接口缺少 `type_name` 也能由 `type` 映射为标签。
- 为兑换码管理提供多选、跨页保留选择、删除已选和明确的删除结果反馈。
- 后端批量删除不得删除已使用或存在使用记录的兑换码。

### 约束条件
```yaml
兼容性约束: 保持现有单条删除接口和 API 响应结构可用
业务约束: 只删除明确勾选的兑换码；保护规则与单条删除一致
UI约束: 遵循现有 Apple 风格表格、蓝色主操作和危险操作二次确认
```

### 验收标准
- [ ] 模板管理的每条记录显示通用、套餐或盲盒礼品卡类型，不依赖 `type_name` 是否存在。
- [ ] 兑换码列表支持勾选、全选当前页、跨页保留选择和删除已选。
- [ ] 删除前显示确认；响应显示已删除与跳过数量；已使用或有使用记录的兑换码仍被保护。
- [ ] 管理端类型检查与生产构建通过，后端 PHP 语法检查通过。

---

## 2. 方案

### 技术方案
- 在 `templates()` 中将映射后的集合写回 paginator，确保后端 `type_name` 实际进入分页响应。
- 模板表格使用 `formatGiftCardTypeLabel(row.type, typeOptions)`，以 `row.type_name` 作为优先展示值，形成前端兼容兜底。
- 新增 `batch-delete-codes` 路由和控制器操作。请求仅接受去重后的 ID 数组，事务内逐项执行与单条删除一致的可删除性检查，返回 `deleted_count`、`skipped_count` 与跳过原因。
- 前端以 ID 集合保存选择状态，表格按当前可见行回显选择；删除后清空成功删除项，保留被跳过项并刷新列表与统计。

### 影响范围
```yaml
涉及模块:
  - 礼品卡管理 API: 修正分页集合并新增受保护的批量删除端点
  - 管理端礼品卡工作台: 类型显示兜底、兑换码多选与批量删除交互
预计变更文件: 5
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 错误删除已使用兑换码 | 高 | 后端逐项复用状态与使用记录检查，前端必须二次确认 |
| 分页后选择状态丢失 | 中 | 用 ID 集合而非当前表格行引用保存选择 |
| 旧后端缺少类型名称 | 中 | 前端由稳定 `type` 与类型映射生成兜底标签 |

### 方案取舍
```yaml
唯一方案理由: 以服务端约束保障数据安全，以客户端选择状态改善操作效率，且不改变既有单条接口。
放弃的替代路径:
  - 前端循环调用单条删除接口: 请求次数多、结果不一致，且无法原子地汇总保护结果。
  - 按当前筛选结果一键全删: 范围不够明确，误删风险过高。
回滚边界: 可独立移除批量路由、控制器方法与前端批量操作；类型显示修复不影响数据模型。
```

## 3. 技术设计

### API设计
#### POST /gift-card/batch-delete-codes
- **请求**: `{ ids: number[] }`，至少 1 个、最多 500 个唯一 ID。
- **响应**: `{ deleted_count, skipped_count, skipped: [{ id, reason }] }`。
- **行为**: 仅删除未使用且无使用记录的兑换码；其余项保留并报告原因。

## 4. 核心场景

### 场景: 删除多条兑换码
**模块**: 礼品卡管理
**条件**: 管理员已勾选一条或多条兑换码。
**行为**: 点击“删除已选”，确认后发送选中 ID。
**结果**: 可删除项被移除，受保护项保留并提示跳过数量。

## 5. 技术决策

### gift-card-type-and-code-bulk-delete#D001: 批量删除只接受已选 ID
**日期**: 2026-07-29
**状态**: ✅采纳
**背景**: 用户需要批量操作，但兑换码可关联真实使用记录。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 接收已选 ID | 删除范围可见、可确认、可审计 | 需要维护前端选择状态 |
| B: 删除筛选结果 | 操作步骤少 | 范围过宽，误删风险高 |
**决策**: 选择方案 A。
**理由**: 与危险操作二次确认和最小作用范围一致。
**影响**: `GiftCardController`、管理端 API 与兑换码列表组件。

## 7. 成果设计

### 设计方向
- **美学基调**: 克制的 Apple 风格运营表格，危险动作收敛在明确的红色按钮与确认对话框中。
- **记忆点**: 工具栏在选中兑换码后即时显示“已选 N 项”和唯一危险操作，范围一目了然。
- **参考**: 用户提供的礼品卡管理截图与项目 `.helloagents/DESIGN.md`。

### 视觉要素
- **配色**: 复用主色 `#0071e3` 与既有危险色 `--xboard-danger`。
- **字体**: 沿用项目系统字体栈，保证与现有管理后台一致。
- **布局**: 在既有工具栏加入选中数量和删除已选按钮，表格首列使用原生选择框。
- **动效**: 仅保留 Element Plus 选择与确认反馈。

### 技术约束
- **可访问性**: 选择框和删除按钮保留文字标签、禁用态与可见焦点。
